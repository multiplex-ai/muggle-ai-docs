## 登录一直失败

**症状：**

- 测试无法通过登录页面
- 报告显示第一步反复失败

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :------------------- | :----------------------------------------------------- |
| 基础 URL 是否正确？ | 确认该网址可从公网访问 |
| 凭据是否为最新？ | 在项目设置的**登录凭据**中更新 |
| 是否启用了 SSO/2FA？ | 改用未启用这些功能的预发布环境 |
| 账户是否被锁定？ | 重置测试账户，或新建一个账户 |

## 网站扫描未发现页面

**症状：**

- 应用中的重要区域从未作为候选流程出现
- 已发现的场景中缺少关键功能

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :----------------------- | :------------------------------------------- |
| 页面是否可访问？ | 确保链接/按钮能通往重要流程 |
| 需要更多起始网址？ | 添加更多网址（例如 `/app/dashboard`） |
| 缺少权限？ | 为测试账户启用功能开关 |
| 页面需要身份验证？ | 提供有效的凭据 |

## 测试不稳定

**症状：**

- 同一脚本有时通过、有时失败
- 两次运行之间没有代码改动

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :------------------------ | :------------------------------------ |
| 实时数据在变化？ | 使用稳定的测试数据或种子数据 |
| 有后台任务在运行？ | 确保测试期间 UI 保持稳定 |
| 时序问题？ | 联系支持团队，并附上失败运行的链接 |
| 依赖第三方服务？ | 对外部服务使用 mock 或 stub |

## API 身份验证错误

**症状：**

- `401 Unauthorized` 响应
- `403 Forbidden` 响应

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :--------------------- | :-------------------------------------------------- |
| API 密钥是否正确？ | 确认密钥与控制台中的一致 |
| 密钥是否已过期？ | 在**设置 → API 密钥**中重新生成 |
| 环境是否正确？ | 检查密钥是否与目标环境匹配 |
| 请求头格式是否正确？ | 使用 `Authorization: Bearer KEY` 或 `x-api-key: KEY` |

## 测试运行超时

**症状：**

- 测试始终无法完成
- 状态卡在 `running`

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :--------------- | :---------------------------------- |
| 网站是否有响应？ | 确认目标环境正常运行 |
| 测试太多？ | 分成更小的批次运行 |
| 网络问题？ | 检查防火墙/代理设置 |
| 页面过重？ | 简化流程或增加超时时间 |

## 报告未生成

**症状：**

- 报告页面没有显示数据
- API 返回空报告

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :----------------- | :-------------------------------------- |
| 运行是否已完成？ | 等待状态变为 `completed` 或 `failed` |
| 权限问题？ | 确认账户拥有报告访问权限 |
| 是否有近期运行？ | 先运行测试，再查看报告 |

## 验证码阻断测试

**症状：**

- 测试在带有验证码的页面上失败
- 智能体请求用户人工处理验证码

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :-------------------------- | :-------------------------------------------------------------------- |
| 验证码类型是否受支持？ | 查看[自动处理验证码](concepts/automated-captcha-handling.md)，了解支持的类型 |
| 滑块或音频验证码？ | 目前尚不支持这些类型；可考虑在未启用这些验证码的预发布环境中测试 |
| 新的验证码实现？ | 联系支持团队，并提供该验证码类型的详细信息 |
| 频繁触发验证码？ | 你的测试账户可能已被标记；尝试使用新账户，或将 IP 加入白名单 |

**提示：** 如有可能，请在预发布环境中关闭验证码，让测试执行更快、更可靠。

## MCP 与本地测试问题

### 找不到 Electron-app

**症状：**

- 错误：“Electron-app not found”
- 测试执行立即失败

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :---- | :------- |
| 安装是否完成？ | 运行 `muggle doctor` 检查状态 |
| 下载失败？ | 运行 `muggle setup` 重试 |
| 网络被拦截？ | 检查防火墙/代理设置 |
| 使用自定义二进制文件？ | 设置 `ELECTRON_APP_PATH` 环境变量 |

### 下载失败并返回 404

**症状：**

- 安装失败，提示“Download failed with status 404”
- 无法安装 electron-app 二进制文件

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :---- | :------- |
| 版本是否已发布？ | 查看 [Releases 页面](https://github.com/multiplex-ai/muggle-ai-works/releases) |
| 版本不匹配？ | 确保包版本与可用的发布版本一致 |
| 开发版本？ | 从源码构建（参见[安装与配置文档](local-testing/setup.md)） |

### MCP 工具未显示

**症状：**

- AI 助手无法识别 `muggle-local-*` 或 `muggle-remote-*` 工具
- “Tool not found”错误

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :---- | :------- |
| 是否已安装包？ | 运行 `npm list -g @muggleai/works` |
| 配置是否正确？ | 检查你所用平台配置文件中的 JSON 语法 |
| 是否已重启客户端？ | 修改配置后重启你的 MCP 客户端 |
| Node 版本？ | 确保已安装 Node.js 22+ |
| 运行诊断 | 执行 `muggle doctor` 找出问题 |

### 浏览器引擎不可用

**症状：**

- 错误：“Browser engine not available”
- 测试执行挂起

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :---- | :------- |
| 浏览器引擎是否已安装？ | 运行 `muggle setup` |
| 端口冲突？ | 检查是否有其他进程占用该端口 |
| 权限问题？ | 确保 electron-app 拥有执行权限 |

### 身份验证问题

**症状：**

- “Not authenticated”错误
- 云端功能不可用

**诊断与解决方法：**

| 检查项 | 解决方法 |
| :---- | :------- |
| 身份验证状态？ | 运行 `muggle status` 检查 |
| 凭据已过期？ | 运行 `muggle login` 重新进行身份验证 |
| 是否已配置 API 密钥？ | 在你的 MCP 配置中设置 `MCP_API_KEY` |
| 网络问题？ | 检查防火墙/代理设置 |
