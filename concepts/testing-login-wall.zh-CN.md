# 测试登录墙后的流程

Muggle Test 会使用你存储在项目中的凭据登录受保护的区域，然后以已登录用户的身份运行流程的其余部分。

## 提供测试账户

请使用专用的测试账户——绝不要使用真实用户的凭据。

| 运行位置 | 如何提供凭据 |
| :------------ | :---------------------------------------------------------------------------------------- |
| **远程**（通过 MCP 测试预发布环境或生产环境） | 保存在项目设置的**登录凭据**中，或存储为项目密钥 |
| **本地**（localhost） | 在指令中提供，或将其保存，以便 `autoLogin` 偏好设置复用 |

已存储的凭据会在多次运行中复用，因此只需设置一次。[`autoLogin` 偏好设置](local-testing/preferences.md)控制 Muggle Test 是静默复用已保存的凭据（`always`）、先询问（`ask`，默认值），还是从不复用（`never`）。

## 指令示例

> “以 `test@example.com` / `Test1234!` 登录 `localhost:3000`，然后打开账单页面，验证页面上显示了当前套餐。”

## SSO 与双重验证账户

自动登录无法完成交互式 SSO 重定向，也无法完成 2FA 一次性密码验证。对于通常需要这些步骤的受限流程：

| 情况 | 建议 |
| :------------------------- | :------------------------------------------------------------------------ |
| 测试账户开启了 2FA | 关闭测试账户的 2FA，或使用未启用 2FA 的测试环境 |
| 仅支持 SSO 登录 | 让 Muggle Test 指向允许密码登录的预发布环境 |
| 账户被锁定或已过期 | 重置或重新创建测试账户 |

如果登录一直失败，请参见[登录一直失败](troubleshooting/common-issues.md#login-keeps-failing)。
