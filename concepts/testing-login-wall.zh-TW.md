# 測試登入牆後的流程

Muggle Test 會使用你儲存在專案中的憑證登入受保護的區域，接著以已登入使用者的身分執行流程的其餘部分。

## 提供測試帳戶

請使用專用的測試帳戶——絕對不要使用真實使用者的憑證。

| 執行位置 | 如何提供憑證 |
| :------------ | :---------------------------------------------------------------------------------------- |
| **遠端**（透過 MCP 測試預備環境或正式環境） | 儲存在專案設定的**登入憑證**中，或儲存為專案密鑰 |
| **本機**（localhost） | 在指示中提供，或將憑證儲存起來，讓 `autoLogin` 偏好設定可以重複使用 |

已儲存的憑證會在各次執行之間重複使用，因此只需設定一次。[`autoLogin` 偏好設定](local-testing/preferences.md)可控制 Muggle Test 要不經詢問直接重複使用已儲存的憑證（`always`）、先詢問（`ask`，預設值），還是一律不重複使用（`never`）。

## 指示範例

> 「以 `test@example.com` / `Test1234!` 登入 `localhost:3000`，接著開啟帳單頁面，確認頁面上顯示目前的方案。」

## SSO 與雙重驗證帳戶

自動登入無法完成互動式 SSO 重新導向，也無法完成 2FA 一次性密碼驗證。對於通常需要這些步驟的受限流程：

| 情況 | 建議 |
| :------------------------- | :------------------------------------------------------------------------ |
| 測試帳戶啟用了 2FA | 停用測試帳戶的 2FA，或使用未啟用 2FA 的測試環境 |
| 僅支援 SSO 登入 | 將 Muggle Test 指向允許密碼登入的預備環境 |
| 帳戶遭鎖定或已過期 | 重設或重新建立測試帳戶 |

如果登入一直失敗，請參閱[登入一直失敗](troubleshooting/common-issues.md#login-keeps-failing)。
