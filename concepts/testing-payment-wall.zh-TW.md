# 測試付費牆後的流程

使用 [Stripe 測試模式](https://docs.stripe.com/testing)測試結帳流程。測試模式的流程與正式模式相同，但絕不會動用真實款項，因此你可以在每次建置時都執行結帳測試。

## 設定

| 步驟 | 動作 |
| :--- | :----------------------------------------------------------------------------------------- |
| 1    | 將應用程式環境設定為使用 Stripe **測試**金鑰（`pk_test_…` / `sk_test_…`） |
| 2    | 確認結帳頁面處於測試模式——Stripe Elements 會顯示「TEST MODE」標示 |
| 3    | 在指示中告訴 Muggle Test 要使用哪張測試卡 |

> ⚠️ 即使在測試模式下，也絕對不要輸入真實的信用卡號碼。使用測試金鑰時，Stripe 會拒絕真實信用卡；而在正式模式金鑰下使用真實信用卡，則會產生真實扣款。

## 測試卡

使用任何**未來**的到期日、任何 3 位數 CVC（American Express 為 4 位數），以及任何郵遞區號。

**付款成功**

| 卡號 | 卡別 |
| :-------------------- | :--------------- |
| `4242 4242 4242 4242` | Visa             |
| `5555 5555 5555 4444` | Mastercard       |
| `3782 822463 10005`   | American Express |
| `6011 1111 1111 1117` | Discover         |

**遭拒與錯誤**

| 卡號 | 結果 |
| :-------------------- | :------------------------------------ |
| `4000 0000 0000 0002` | 一般性遭拒 |
| `4000 0000 0000 9995` | 餘額不足 |
| `4000 0000 0000 0069` | 卡片已過期 |
| `4000 0000 0000 0127` | CVC 錯誤 |
| `4000 0000 0000 0119` | 處理錯誤 |

**3D Secure / 需要身分驗證**

| 卡號 | 結果 |
| :-------------------- | :---------------------------------------------- |
| `4000 0025 0000 3155` | 跳出 3D Secure 身分驗證步驟 |
| `4000 0027 6000 3184` | 每筆交易都需要身分驗證 |

Stripe 在 [docs.stripe.com/testing](https://docs.stripe.com/testing) 提供完整清單，其中包括特定銀行的遭拒情形、爭議模擬，以及用於訂閱的測試時鐘。

## 指示範例

> 「在 `localhost:3000/cart` 測試結帳。加入 Pro 方案，前往結帳，使用 Stripe 測試卡 `4242 4242 4242 4242` 付款，到期日 `12/34`、CVC `123`、郵遞區號 `12345`。確認有出現訂單確認頁面。」

若要測試失敗路徑，請改用會遭拒的卡片，並確認你的應用程式顯示正確的錯誤：

> 「使用會遭拒的卡片 `4000 0000 0000 0002` 再次結帳，確認頁面出現『Your card was declined』訊息，且沒有建立訂單。」
