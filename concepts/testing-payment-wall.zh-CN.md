# 测试付费墙后的流程

使用 [Stripe 测试模式](https://docs.stripe.com/testing)测试结账流程。测试模式与真实模式的流程相同，但不会动用真实资金，因此你可以在每次构建时都运行结账测试。

## 设置

| 步骤 | 操作 |
| :--- | :----------------------------------------------------------------------------------------- |
| 1    | 将应用环境配置为使用 Stripe **测试**密钥（`pk_test_…` / `sk_test_…`） |
| 2    | 确认结账页面处于测试模式——Stripe Elements 会显示“TEST MODE”标识 |
| 3    | 在指令中告诉 Muggle Test 使用哪张测试卡 |

> ⚠️ 即使在测试模式下，也绝不要输入真实的银行卡号。使用测试密钥时，Stripe 会拒绝真实银行卡；而在真实模式密钥下使用真实银行卡，会造成真实扣款。

## 测试卡

使用任意**未来**的有效期、任意 3 位 CVC（American Express 为 4 位），以及任意邮政编码。

**支付成功**

| 卡号 | 卡组织 |
| :-------------------- | :--------------- |
| `4242 4242 4242 4242` | Visa             |
| `5555 5555 5555 4444` | Mastercard       |
| `3782 822463 10005`   | American Express |
| `6011 1111 1111 1117` | Discover         |

**被拒与错误**

| 卡号 | 结果 |
| :-------------------- | :------------------------------------ |
| `4000 0000 0000 0002` | 一般性被拒 |
| `4000 0000 0000 9995` | 余额不足 |
| `4000 0000 0000 0069` | 卡已过期 |
| `4000 0000 0000 0127` | CVC 错误 |
| `4000 0000 0000 0119` | 处理错误 |

**3D Secure / 需要身份验证**

| 卡号 | 结果 |
| :-------------------- | :---------------------------------------------- |
| `4000 0025 0000 3155` | 弹出 3D Secure 身份验证步骤 |
| `4000 0027 6000 3184` | 每笔交易都需要身份验证 |

Stripe 在 [docs.stripe.com/testing](https://docs.stripe.com/testing) 维护着完整列表，其中包括特定银行的被拒情形、争议模拟，以及用于订阅的测试时钟。

## 指令示例

> “在 `localhost:3000/cart` 上测试结账。添加 Pro 套餐，进入结账页面，使用 Stripe 测试卡 `4242 4242 4242 4242` 付款，有效期 `12/34`，CVC `123`，邮编 `12345`。验证订单确认页面出现。”

要测试失败路径，请换用会被拒的卡，并验证你的应用显示了正确的错误：

> “使用被拒卡 `4000 0000 0000 0002` 再次结账，验证页面显示‘Your card was declined’消息，且没有创建订单。”
